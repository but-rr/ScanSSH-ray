# ScanSSH-ray

**Рабочая версия v0.1.5 для Windows 10**

### ⬇️ [Скачать ScanSSH-ray для Windows](https://github.com/but-rr/ScanSSH-ray/releases/latest)

## Стек проекта

- **Svelte + TypeScript** — интерфейс.
- **Wails v2** — desktop-приложение.
- **Go SSH + OpenSSH** — SSH-подключения.

## Возможности

- Мониторинг выбранного пула.
- Статусы SSH, интернета через прокси и доступности ПК.
- Поиск, фильтры, журнал событий в отдельном полупрозрачном окне по кнопке в левой панели.
- При запуске выбран **Turbo**: только ПК с подтверждённым SSH и интернетом, по возрастанию отклика SSH. Список пересортировывается при обновлении результатов.
- В фильтре **«Все»** сначала идут ПК с интернетом, остальные проверенные и ещё не проверенные. Внутри групп — по отклику. Отклик измеряет задержку SSH.
- Настройки SSH, прокси, портов и SSH-ключей.
- Графитовый интерфейс с компактной панелью навигации и отдельной кнопкой управления туннелем. Длинный список устройств прокручивается внутри таблицы с закреплёнными заголовками.
- Сводные карточки работают как фильтры. Пул можно выбрать в раскрывающемся блоке над таблицей или через кнопку «Пулы IP-адресов» слева; поиск открывается клавишей `/`.
- Подробности соединения и справочная SSH-команда раскрываются по нажатию. Окна закрываются клавишей `Esc`, после закрытия фокус возвращается на предыдущий элемент.
- Выбор ПК и кнопка **«Перенаправить трафик»**.
- Нажатие на IP в таблице выбирает ПК и копирует адрес в буфер обмена. IP в карточке выбранного устройства тоже можно скопировать нажатием.
- Кнопка **«Проверить ПК»** в карточке устройства:
  - Немедленная проверка SSH и интернета выбранного адреса без ожидания интервала проверки прокси.
  - Остальные ПК не проверяются этой кнопкой.
  - Во время текущей проверки повторный запуск недоступен; её можно остановить кнопкой сверху.
  - Автопроверка остальных устройств продолжает работать по своим интервалам.

## Туннель

Кнопка **«Перенаправить трафик»** открывает настоящий локальный порт:

```text
приложение → 127.0.0.1:3128 → SSH выбранного ПК → 10.0.0.1:3128
```

Она же выполняет `.cmd`-файл с SSH-туннелем:

```bash
ssh -L 3128:10.0.0.1:3128 admin@ip_pc
```

## Запуск

1. Заполните `.env`:

   ```dotenv
   SSH_USER='admin'
   SSH_KEY_PATH='C:/Users/admin/.ssh/id_ed25519'
   PROXY_HOST='10.0.0.1'
   PROXY_PORT=3128
   PROXY_AUTH='basic'
   PROXY_USER='YOUR_LOGIN'
   PROXY_PASSWORD='YOUR_PASSWORD'
   ```
2. Запустите `ScanSSH-ray.exe`.
3. Новые ключи SSH-серверов принимаются и сохраняются автоматически при первом подключении. Для известного ключа выполняется проверка по `known_hosts`; его изменение блокирует соединение.
4. После изменения `.env` нажмите «Настройки → Перечитать». Действующий туннель при этом закрывается.
Нужен Microsoft Edge WebView2 Runtime. Встроенный загрузчик предложит установить его при отсутствии; для установки требуется интернет.

## Проверка доступности

1. **TCP (порт 22)** — проверка доступности SSH-порта.
2. **SSH** — авторизация с использованием привязанных ключей.
3. **Интернет** — удалённая проверка через корпоративный прокси с авторизацией.
4. **Кэширование** — сохранение результатов и переиспользование SSH-сессий.
5. **Автообновление** — отдельные интервалы проверки SSH и интернета.

## Проверка интернета

На целевом ПК должны работать OpenSSH Server, `powershell.exe` и `curl.exe`. Настройки curl передаются по стандартному вводу SSH-канала. Логин/пароль отсутствуют в аргументах процесса, интерфейсе, журнале и отчётах; временные файлы с паролями на удалённых ПК не создаются.

По умолчанию программа выполняет HTTP HEAD к `http://www.google.com`, аналогично команде:

```bash
curl.exe -I -x http://ПРОКСИ:ПОРТ -U "ЛОГИН:ПАРОЛЬ" http://www.google.com
```

**Результаты проверки:**

- **Успех** — HTTP 2xx или 3xx.
- **Неудача** — ответы 403 и 407, таймауты и ошибки выполнения. Отображаются с пояснением.

Проверка подтверждает доступ к выбранному ресурсу.

Для прокси без авторизации задайте:

```dotenv
PROXY_AUTH='none'
```
